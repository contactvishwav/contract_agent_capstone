# Verified system map and current limitations

Audit basis: branch base `4868676`, preserved session commit `d2b3c94`, governance commit `70459b4`, tenant-boundary hardening, and the local-stack/browser verification completed on 2026-08-08. Paths below cite current file lines/symbols. “Verified” means the stated evidence was inspected; browser/runtime claims are labeled separately from code/test claims.

## Authentication and tenant identity

- Bootstrap registration accepts a requested new tenant but rejects tenants that already have users (`backend/api/auth_api.py:96-133`, `UserRepository.create_user`). Login verifies stored credentials and signs stored account tenant/role (`auth_api.py:136-161`). JWT validation verifies signature/expiry and requires tenant/role claims (`backend/governance/auth.py:123-168`); RBAC returns that identity (`backend/governance/rbac.py:53-87`).
- Admin invitations derive tenant from the authenticated admin, while acceptance derives tenant/role from the stored hashed invite (`auth_api.py:292-363`). Google OIDC is invite-gated for new users (`backend/api/sso_api.py:94-167`). TOTP setup/confirm/verify and backup codes are implemented (`auth_api.py:167-267`, `backend/governance/mfa.py`).
- HTTP analysis/upload/search/chat routes inspected use `requires_permission(...)` and `identity.tenant_id`. Celery analysis receives the tenant explicitly (`backend/api/contract_intelligence.py:27-53`; `backend/tasks.py:116-141`). Contract/chat repositories generally predicate Contract/ChatSession reads by tenant.
- **Hardened 2026-08-08:** task/workflow status now requires a real Redis ownership marker keyed by environment/tenant/task and fails closed when shared ownership storage is unavailable (`backend/infrastructure/task_ownership.py`; `backend/api/contract_intelligence.py`; `backend/api/supervisor_api.py`). Audit/error writes require explicit tenant or explicit system scope, reads contain tenant predicates, and agent audit metadata excludes prompt/tool payload content (`backend/infrastructure/audit_logger.py`; `error_tracker.py`; `agent_audit_service.py`; `backend/api/audit_api.py`).
- **Remaining default-tenant classification:** tests/examples are safe fixtures; standalone MCP tenant assertion is development-only behind explicit opt-in; legacy enterprise/audit migrations contain sample/demo data and must not be rerun or used to infer ownership on populated graphs; default parameters remain in older contract/document/PDF/chunk/CUAD paths and are production-reachable risks requiring a separate compatibility-focused task. Some Section/Clause parent-ID matches also remain unscoped. Do not treat these as resolved.

## Document lifecycle

1. React uploads multipart PDF/model to `/api/documents/upload` (`frontend/src/components/features/contracts/DocumentUpload.tsx:32-121`). The backend validates permission/type/size/content and identifies active duplicates by tenant-scoped SHA-256 source hash, so a corrected file may keep the same filename while an archived file may be uploaded again (`backend/api/document_upload.py`).
2. A temporary file is parsed by pypdf then pdfplumber fallback, off the event loop with a timeout (`backend/infrastructure/text_extractors.py:33-123`). **No OCR engine exists**; scanned/image-only PDFs are not handled beyond these text extractors.
3. The route performs chunking/embeddings and then invokes the LangGraph PDF workflow (`document_upload.py:181+`; `backend/agents/pdf_processing_agent.py:14-173`; `DocumentProcessingService._process_with_agent`). The workflow reuses extracted text, runs LLM metadata analysis, and persists a tenant-scoped Contract.
4. Contract storage encrypts/redacts full text and writes metadata/relationships/embedding (`backend/infrastructure/contract_repository.py:81-237`). Separate Section, Clause, Document/Chunk models coexist; enhanced processing can create section/clause/relationship embeddings. Native indexes cover Contract, Section, Clause, Chunk, and PolicyDocument families (`backend/migrations/vector_index_migration.py`, `backend/shared/utils/vector_index_config.py`).
5. Upload and intelligence analysis are separate. The frontend enqueues `/api/intelligence/contracts/{id}/analyze`, polls `/tasks/{task_id}/status`, and renders results (`ContractIntelligence.tsx`; `backend/api/contract_intelligence.py:27-86`).
- **Known gaps:** Section/Clause repositories match parent IDs without tenant predicates and rely on globally unique IDs; several legacy/new chunk models coexist. New chunk creation and enhanced embedding status/write paths now scope the owning Document by tenant, but older local `Chunk` nodes do not carry their own tenant property and remain scoped through their owning Document. `multi_level_embeddings.py` contains destructive delete/rebuild statements and must never be casually rerun against populated data. The reported Document Analysis server error disappeared once the backend was reachable; a fresh `Clean_MSA.pdf` analysis then completed through the real worker and default planned path.

### Source-PDF and page provenance (implemented; locally browser verified)

- Before ADR-005, standard and enhanced upload deleted the only PDF after concatenated text extraction; original bytes, page boundaries, and viewer coordinates were not durable. No OCR engine exists. Legacy contracts therefore remain excerpt/section/clause-only unless the exact original is explicitly re-uploaded through the tenant-scoped duplicate path; pages are never invented.
- New uploads use page-aware pypdf/pdfplumber extraction and retain exact bytes through AES-GCM `PdfSourceStorage`. The opaque storage key plus page count/method/text-layer metadata live on the active tenant-owned Contract. Encrypted `SourcePage` nodes carry tenant/contract-bound IDs, PDF page number, page-local text, global spans, and extraction version (`backend/infrastructure/text_extractors.py`; `backend/infrastructure/pdf_source_storage.py`; `backend/application/services/pdf_provenance_service.py`; `backend/migrations/pdf_source_schema_migration.py`).
- `GET /api/documents/{contract_id}/source` requires Analyze permission, derives tenant from JWT, revalidates active ownership, resolves only the server record, and uses a common 404, PDF content type, encoded filename, and private no-store caching (`backend/api/document_upload.py:get_source_pdf`). The browser passes authenticated response bytes directly to PDF.js; no public/object URL, tenant, excerpt, token, or storage path is exposed. Vite packages PDF.js's local standard-font/CMap assets so the private PDF text layer remains functional without third-party asset requests (`frontend/src/components/features/contracts/PdfCitationViewer.tsx`; `frontend/vite.config.ts`).
- Citation locators are recomputed on creation and restoration. A unique whitespace-normalized page-text match permits an exact highlight; a verified mapped chunk permits page-only navigation; otherwise the UI shows section/clause/excerpt-only or unavailable/image-only state (`PdfProvenanceService`; `enrich_citations_with_provenance`; `message.tsx`; ADR-005). Exact PDF text-layer coordinates and OCR remain deliberately unsupported.

## Default analysis execution

`POST .../analyze` defaults `use_planning=True`, derives tenant from JWT, and enqueues `analyze_contract_task` (`backend/api/contract_intelligence.py:27-53`). The task calls `ContractIntelligenceService.analyze_contract_by_id`, loads tenant-scoped Contract text, creates `IntelligenceOrchestrator`, and selects planning by default (`backend/tasks.py:116-141`; `contract_intelligence_service.py:20-101`; `contract_intelligence_agents.py:383-405`).

Planning creates a plan with `PlanningAgent` and executes `PlanExecutionEngine` (`contract_intelligence_agents.py:417-470`). The engine executes dependency-ordered extraction, policy checking, risk, CUAD mitigation, redlines, and validation; records per-step status; formats grounding/quality/escalation; and persists the result (`backend/agents/planning/execution_engine.py:389-628`; `contract_intelligence_service.py:219-319`). Extraction uses structured output and deterministic source-span grounding; policy evaluation combines deterministic numeric rules with LLM evaluation; CUAD mitigation has its own Phase3→Phase2→Phase1 degradation.

**Execution identity:** domain conversion, task serialization, immutable `AnalysisRun` persistence, latest-analysis retrieval, and the frontend now preserve `execution_path`, `planned_execution`, `analysis_method`, and the actual model (`backend/application/services/intelligence_result_serializer.py`; `contract_intelligence_service.py:_store_intelligence_results`; `backend/api/contract_intelligence.py:get_latest_contract_analysis`; `frontend/src/components/features/intelligence/ContractIntelligence.tsx`). The orchestrator still falls back to traditional LangGraph on a planning exception (`contract_intelligence_agents.py`), so tests and reviews must assert these identity fields rather than infer the path from plausible content.

## Contract Chat and persistent sessions

- Entry is authenticated SSE `POST /api/run/` (`backend/main.py:550-577`). It chooses a prebuilt provider-specific LangGraph agent from `LLMManager` (`backend/llm_manager.py:37-93`), runs prompt/output guards, streams assistant/tool events, and injects JWT tenant/correlation/contract scope through LangGraph config (`main.py:324-547`; `backend/contract_chat_agent.py:22-211`). Tool failures generally raise through the graph; the MCP bridge alone normalizes failures.
- Commit `d2b3c94` adds tenant-scoped ChatSession/ChatMessage nodes, encrypted content, sequence relationships, migration indexes/constraints, list/create/detail routes, and SSE persistence (`backend/infrastructure/chat_session_repository.py:58-181`; `backend/api/chat_sessions.py`; `backend/migrations/chat_session_schema_migration.py`). User text persists before model invocation; guarded rejection and final guarded/redacted AI text persist; tool calls/results persist during the stream (`backend/main.py`). Natural-language user/AI messages—but not tool messages—are replayed to the model.
- Frontend tenant-owned providers mount inside the authenticated tenant boundary. `ChatProvider` persists across in-app navigation; `ChatSessionContext` and `ContractHistoryContext` reset/refetch on tenant changes; the latter bootstraps contract labels from authenticated `GET /api/documents` and uses tenant-scoped local storage only as a cache (`frontend/src/App.tsx`; `frontend/src/contexts/ChatSessionContext.tsx`; `frontend/src/contexts/ContractHistoryContext.tsx`). The switcher fetches active-session detail during restore, permits active-row retry, and displays conversation title separately from filename/scope (`SessionSwitcher.tsx`).
- Chat citations are derived only from structured tool results, then revalidated against authenticated tenant plus active Contract state before SSE, persistence, and every restore. Citation metadata is encrypted with the message and carries provider-neutral source identifiers; absent page metadata remains absent (`backend/application/services/chat_citation_service.py`; `backend/main.py:runner`; `backend/infrastructure/chat_session_repository.py`; `backend/api/chat_sessions.py`). Assistant Markdown uses GFM plus an HTML/URL sanitization boundary; user and raw tool text do not use the Markdown renderer (`frontend/src/components/features/contracts/message.tsx`). Session rename is tenant-scoped, validated, model-free, and persistent (`backend/api/chat_sessions.py:rename_session`; `SessionSwitcher.tsx`).
- **Browser/runtime verified 2026-08-08:** multiple distinct sessions for one contract plus an All-Contracts session; suggestion-button submission through the normal SSE path; first-turn live rendering; active/different row switching; ordered user/tool-call/tool-message/AI replay; navigation, refresh, and logout/login restoration; tenant change clearing; filename-labeled contract options; locked server-authoritative scope; and actual `gemini-2.5-flash` attribution. Neo4j independently showed ordered messages and matching tool-call IDs per tested session. Stream-runner exceptions and cancellation persist a safe terminal AI state.
- **Output validation repaired and locally verified 2026-08-08:** safety and hallucination validators use the raw provider model rather than recursively invoking the compiled Contract Chat graph. Output Guard is a sequential, fail-closed chain with deterministic aggregation; generated assistant content is buffered until every required validator passes; timeout cancels the awaited validator path; and bounded terminal states (`passed`, `rejected`, `validation_failed`, `timed_out`, `cancelled`, `empty`, `generation_failed`, or `persistence_failed`) flow through SSE, persistence, restoration, audit, and metrics (`backend/governance/base.py`; `backend/governance/validators/`; `backend/main.py:_validate_output_guard`; `backend/main.py:runner`; `backend/infrastructure/chat_session_repository.py`; ADR-004). A nullable `ChatMessage.terminal_status` preserves legacy-row compatibility. **Remaining gap:** provider attribution records the model selected by the executed LLM path, but there is no independent provider-response attestation.
- **Stop Generating verified 2026-08-08:** each persistent browser run carries an opaque UUID registered against the JWT-derived tenant and server-authoritative session. The authenticated cancel route revalidates session ownership, cancels the executing async provider/tool/Output Guard stream, waits for durable `cancelled` persistence, and only then acknowledges the browser. Completion wins after a terminal assistant record is durably stored; cancellation cannot overwrite it (`backend/main.py:ChatRunRegistry`; `cancellable_chat_stream`; `cancel_chat_run`; `frontend/src/components/features/contracts/provider.tsx`; `input.tsx`). Session switch/new chat waits for cancellation cleanup; navigation/logout/unmount initiate the same handshake. The registry deliberately matches the production deployment's single FastAPI process; a future multi-process API deployment requires a distributed task-cancellation ADR/design.

### Model selection and attribution (implemented; provider matrix incomplete)

- `backend/model_registry.py` is the server authority for stable ID→private provider API name, safe label, credential-derived configured status, workflow capabilities, production allowance, fallback eligibility, cost/latency class, and deprecation. Authenticated `GET /api/models` returns only safe compatible choices plus the fixed 1536-dimensional `gemini-embedding-001` contract. Frontend chat and analysis selectors consume it (`backend/api/model_registry_api.py`; `frontend/src/services/modelRegistryApi.ts`; ADR-006).
- Standard/enhanced upload, analysis, Supervisor, and chat validate stable IDs before provider/task dispatch. `LLMManager.raw_llms` contains exact structured-output provider clients while `agents` contains provider-specific compiled chat graphs. Analysis threads the selected raw model through Celery→orchestrator→`PlanExecutionEngine`/traditional tools; provider failure now fails the task rather than returning a plausible empty/fallback result (`document_upload.py`; `enhanced_document_upload.py`; `contract_intelligence.py`; `supervisor_api.py`; `contract_intelligence_service.py`; `llm_manager.py`).
- Chat persists requested/actual model and provider, fallback flag/reason, prompt version, execution path, and terminal status per assistant message. Switching changes only subsequent turns; restored provider-neutral history preserves old attribution (`backend/main.py`; `chat_session_repository.py`; `chat_sessions.py`; `frontend/.../sessionMessages.ts`; `message.tsx`). Immutable `AnalysisRun` serialization similarly keeps requested and actual attribution rather than relabelling a restored run (`intelligence_result_serializer.py`; `ContractIntelligence.tsx`).
- Automatic cross-provider fallback is disabled for legal chat and analysis. The older fallback service remains used by explicitly separate/internal paths and is not authorization to substitute at these boundaries. Current “actual” identity proves which configured server client executed, but is not independent provider-response attestation. Locally configured provider availability and paid/live evidence must be recorded per verification run without exposing credential values.

## Enhanced Search and RAG

- REST: authenticated `/api/contracts/search/*` constructs `SearchParams` with JWT tenant and dispatches `EnhancedSearchService` to four strategies (`backend/api/enhanced_contract_search.py:53-165`; `backend/application/services/enhanced_search_service.py:45-115`). Document/section/clause vector thresholds are `0.3`; relationship similarity is `0.3`; results use `SearchResult`/API mapping and a tenant-inclusive Redis hash key (`backend/shared/utils/search_strategies.py:77-375`).
- Tool-facing: Contract Chat's `EnhancedContractSearchTool` supports document, section, clause, relationship, chunk, and all-level search; richer governing-law/monetary/aggregation filters; raw Cypher-shaped results; its own cache key; and thresholds `0.8` (chunk `0.7`) (`backend/shared/utils/enhanced_contract_search_tool.py:27-216,220-634`). Contract scope is server-injected for this tool.
- Both use native vector indexes, optional Gemini/provider-fallback re-ranking (30 candidates→10), tenant-inclusive cache keys, and graceful re-ranking degradation. They intentionally remain separate. Vector retrieval globally overfetches before post-filtering tenant, so recall for a tenant can be reduced when global top-K is dominated by other tenants even though returned rows remain filtered.

## Data and infrastructure

- Neo4j is the durable store for Contracts, immutable AnalysisRuns, Parties/Countries, Sections/Clauses/types, Documents/Chunks plus legacy DocumentChunks, policies, users/invites/MFA state, audit/error/metrics/learning nodes, SourcePages, and ChatSession/ChatMessage history. `run_all_migrations.py:MIGRATIONS` currently registers 14 versioned migrations through SchemaMigration nodes.
- Redis is Celery broker/result backend (`backend/celery_app.py:7-84`), response/vector cache, rate-limit storage, circuit-breaker state, LLM usage/latency/hallucination and task counters, and supervisor pub/sub. In-memory fallbacks exist for local/test use; they do not provide cross-process semantics.
- Celery owns long-running single-contract analysis. Submission now reserves a real-Redis ownership marker before publish; task and Supervisor status authorize against it before constructing `AsyncResult`. Unknown, expired, corrupt, and other-tenant IDs share `404`; Redis failure returns `503` without reading Celery. Markers expire after 24 hours with Celery results, and enqueue failure removes the marker best-effort (`backend/infrastructure/task_ownership.py`). Explicit request-level idempotency keys are still not implemented.
- Supervisor live-progress channels are namespaced by environment plus hashed tenant/contract identifiers. Stream routes additionally verify the contract with authenticated tenant scope. Pub/sub remains non-durable and same-contract concurrent runs can interleave.
- Monitoring includes health routes, Prometheus middleware/metrics, circuit breakers, rate limiting, encryption, and Neo4j audit/error records. Audit tenant accuracy gaps are noted above. `/metrics` is intentionally unauthenticated and assumes network restriction (`backend/main.py:202-214`).
- Production is a single GCP e2-micro: backend 300m, worker 280m with solo concurrency, Redis 160m, UI 40m, Caddy 64m; total limits about 844 MiB plus swap (`docs/DEPLOYMENT.md:248-264`, `docker-compose.prod.yml`). Local success does not establish production fit.

## Frontend journeys and persistence

- Navigation is in-memory, not URL routing (`frontend/src/lib/useRouter.ts:1-16`); refresh returns to Intelligence except the special invite URL. Authentication persists JWT-derived session via `authStore`; `apiFetch` adds Bearer and clears on 401 (`frontend/src/lib/apiClient.ts:1-35`).
- Document Analysis uploads, enqueues through real Redis/Celery, polls, and renders. Recent contract metadata now bootstraps from the authenticated tenant-scoped documents endpoint and tenant-scoped cache. The result UI exposes the real model and `PlanExecutionEngine` versus fallback/traditional identity. A fresh `Clean_MSA.pdf` browser run completed in 35.26 seconds with `execution_path=plan_execution_engine`, `planned_execution=true`, and `analysis_method=optimized_phase3`.
- Recent Contracts is an accessible, single-selection control shared with the analysis panel. The selected contract is tenant-keyed convenience state, but `GET /api/intelligence/contracts/{id}/analysis` is the source of truth: it restores the latest encrypted full AnalysisRun without invoking a model, resumes in-flight polling, labels aggregate-only legacy records, and prevents stale responses from replacing a newer selection (`IntelligencePage.tsx`; `ContractIntelligence.tsx`; `backend/api/contract_intelligence.py`).
- Chat state and remaining gaps are described above. Suggested queries are accessible buttons queued into the same normal submit path as typed prompts and have focused component coverage plus live Gemini/browser evidence.
- Enhanced Search is a separate authenticated page calling the REST implementation. Documentation/Supervisor tabs are static displays; they are not runtime proof. `SupervisorPage.tsx:225-231` still says provider switching is unbuilt, contradicting the implemented extraction/reranker fallback chain.
